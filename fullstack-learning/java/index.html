01 01 · 从浏览器走向 JVM

理解 Java 的运行模型

先建立源代码、编译器、字节码与运行环境之间的关系。

Java 不只是另一种语法

前端常见流程是编写 TypeScript，再由工具转换成浏览器可执行的 JavaScript。Java 的基本流程是：编写 .java 源文件，用 javac 编译成 .class 字节码，再让 JVM 执行字节码。编译阶段会检查类型、方法调用和语法，但不能证明程序业务正确，也不能消除空指针、越界等运行时问题。先把“编译失败”和“运行失败”分开判断，排错效率会高很多。

JDK 是开发工具包，包含 javac、java、标准库和运行所需组件。JVM 是 Java 虚拟机，负责加载类、执行字节码、管理内存；运行中可以通过 JIT 把热点代码编译为机器码。“一次编译，到处运行”依赖目标机器有兼容 JVM，并不意味着文件路径、原生库和操作系统差异会自动消失。

先确认工具来自同一个 JDK

终端命令，不写进 Java 文件：

java --version
javac --version

本指南使用 Java 21，不启用预览特性。版本应当是 21 或兼容环境。系统安装多个 JDK 时，java 与 javac 可能指向不同目录，出现“编译成功却无法运行”。新版编译器默认生成的字节码，不一定能由旧 JVM 执行；需要兼容 Java 21 时可以显式指定 --release 21。

最小构建流水线

完整可运行文件：Lifecycle.java

public class Lifecycle {
    public static void main(String[] args) {
        System.out.println("source → bytecode → JVM");
    }
}

在 Lifecycle.java 所在目录执行的终端命令：

javac --release 21 Lifecycle.java
java Lifecycle

第一条命令生成 Lifecycle.class，第二条给的是类名，不是 Lifecycle.class 文件名。类加载器根据类路径寻找字节码；在当前目录执行这个例子时，默认类路径通常足够。源文件运行模式 java Lifecycle.java 也受支持，但它会隐藏编译这一步，初学阶段建议先手动编译一次。

项目变大以后会增加什么

Maven 或 Gradle 负责管理依赖、编译、测试和打包，它们不是 Java 语法，也不替代 JVM。JAR 是归档格式；只有设置了正确入口等信息的可执行 JAR，才适合用 java -jar 直接启动。后端框架如 Spring Boot 则提供应用组织方式和基础能力，仍然建立在类、方法、异常和集合这些语言基础上。

不要把 JVM 的垃圾回收理解为“所有资源都自动释放”。对象占用的堆内存可以被回收，但文件、网络连接、数据库连接等资源仍需要明确的生命周期管理。

已经修改源代码，但运行结果还是旧的，最先检查什么？

参考答案

检查是否重新运行 javac、编译是否成功，以及 java 是否从正确目录或类路径加载了刚生成的 .class。修改 .java 并不会同步改写旧字节码。

02 02 · 文件、类与入口

写出第一个完整程序

能自己编译、运行并读懂每一个符号，才算真正开始。

先写全，不依赖框架模板

新建名为 HelloJava.java 的 UTF-8 文本文件。Java 区分大小写，HelloJava、helloJava 与 hellojava 是不同名字。下面是完整的 Java 21 程序，复制到文件后可以直接编译运行，不需要额外依赖。

完整可运行文件：HelloJava.java

public class HelloJava {
    public static void main(String[] args) {
        String name = args.length > 0 ? args[0] : "Java";
        System.out.println("你好，" + name + "！");
    }
}

把入口声明逐个拆开

  • public class HelloJava 声明一个公开类。使用 javac 时，公开顶层类名称必须与源文件名一致，包括大小写。
  • public 表示入口可被外部访问；static 表示调用时不需要先创建 HelloJava 对象。
  • void 表示方法不返回结果。main 是启动器识别的入口名称，不是随便取的名字。
  • String[] args 是命令行参数数组，数组元素是字符串。args[0] 是第一个用户参数，不是程序名。
  • 花括号组成代码块；普通声明和表达式语句通常以分号结尾。if、方法或类的代码块后一般不加分号。
  • System.out.println 调用标准输出对象的方法，打印后换行。字符串用双引号；单引号表示单个 char 字面量。

在文件所在目录执行的终端命令：

javac -encoding UTF-8 HelloJava.java
java HelloJava
java HelloJava Alice
java HelloJava "Frontend Engineer"

最后一个命令的引号由终端解释，用于把含空格的内容作为一个参数。没有参数时 args.length 等于 0，程序使用默认名称；直接读取 args[0] 则会数组越界。这里的条件表达式只会求值被选中的分支，因此空数组时不会访问 args[0]。

先学会区分三种错误

漏掉分号、把 println 拼错或类型不匹配，会让 javac 编译失败。数组越界通常在运行时出现异常。输出结果与需求不符却没有报错，则是逻辑错误。面对报错，优先看第一条有效错误和它对应的源文件行号，不要只盯着最后一行。

Java 没有要求所有东西都必须写 public。一个源文件可以包含非公开的顶层类，但入门阶段保持“一份文件一个同名公开类”最直观。后续引入 package 时，类有包名构成的完整名称，目录与启动方式也需要对应调整，不要随意将不同教程的片段混到一个文件里。

注释有 // 单行注释和 /* 多行注释 */。注释适合解释意图，而不是把每行代码再翻译一遍。变量、方法通常使用 lowerCamelCase，类使用 UpperCamelCase。

动手练习

让程序在有第二个参数时打印它，否则打印“没有第二个参数”。下面片段应该放在哪里？

参考答案

片段：放在 HelloJava.main 方法体内。

if (args.length >= 2) {
    System.out.println(args[1]);
} else {
    System.out.println("没有第二个参数");
}

03 03 · 不再只有 number

类型、变量与精度

理解基本类型、引用、类型转换与金额计算的边界。

八种基本类型必须分清

Java 的类型在编译时确定。byte、short、int、long 是有符号整数，分别占 8、16、32、64 位；float、double 是 32、64 位浮点类型；char 是 16 位 UTF-16 代码单元；boolean 表示 true 或 false，Java 语言不规定其统一存储大小。常规整数优先 int，可能超出范围时使用 long；普通浮点运算常用 double。

片段：放在任意 main 方法体内，无额外 import。

byte level = 10;
short year = 2026;
int count = 100_000;
long population = 8_000_000_000L;
float ratio = 0.5F;
double score = 98.6;
char grade = 'A';
boolean passed = true;

整数大字面量加 L，float 字面量加 F，否则通常分别按 int 和 double 处理。局部变量读取前必须明确赋值，不能依赖默认值；实例字段、静态字段和数组元素有默认值，例如数字 0、boolean 的 false、引用的 null。这个区别经常让从 JavaScript 转来的开发者意外。

引用与 null 不是“任意类型”

String、数组和自定义类都是引用类型。变量保存引用，null 表示没有指向对象；int 不能是 null，包装类型 Integer 可以。Java 没有 JavaScript 的 undefined，也不会把空字符串、0、null 隐式当作 false。访问 null 引用的方法会抛出 NullPointerException。

片段：放在 main 方法体内，无额外 import。

Integer boxed = 42;      // 自动装箱：int → Integer
int unboxed = boxed;    // 自动拆箱：Integer → int
Integer missing = null;
// int broken = missing; // 编译通过，运行时拆箱抛出空指针异常
long widened = 123;
double approximate = 9_007_199_254_740_993L; // 可能丢精度
int truncated = (int) 3.9; // 向零截断，得到 3
byte wrapped = (byte) 130; // 得到 -126，不是范围校验

转换、推断与不可重新赋值

小范围数值常可自动转换为更宽类型，但“更宽”不总意味着精度无损，例如 long 转 double。窄化转换通常需要强制类型转换，而且可能截断或溢出；它不是合法性验证。byte、short、char 参与常规算术时通常先提升为 int。

var 是局部变量类型推断，不是动态类型：var name = "Lin" 推断为 String，之后不能赋值整数。var 不能用于字段、方法返回类型或以 null 作为唯一初始化信息。final 禁止变量再次赋值，但引用所指对象仍可能可变，因此它更像限制绑定，而不是深度冻结。

片段：放在 main 方法体内；文件顶部添加 import java.math.BigDecimal;

var name = "Lin";
final int[] values = {1, 2};
values[0] = 9; // 合法：修改数组，不是重新给 values 赋值
BigDecimal price = new BigDecimal("0.1");
BigDecimal total = price.add(new BigDecimal("0.2"));
System.out.println(total); // 0.3

二进制浮点数无法精确表示所有十进制小数。金额常用 BigDecimal 或按最小货币单位表示的整数。优先从十进制字符串构造 BigDecimal，避免 new BigDecimal(0.1) 把已有浮点误差带进去；除法还应明确舍入规则。

动手练习

为什么 final StringBuilder text = new StringBuilder(); 后面仍能调用 text.append("A")？

参考答案

final 限制 text 这个变量不能再指向另一个对象，不限制 StringBuilder 内部内容变化。要获得不可变值，应选择不可变类型，例如 String，并注意其引用本身是否需要 final。

04 04 · 编译成功不等于算对

运算符与判断陷阱

避免整数除法、溢出、引用比较和短路求值中的隐蔽错误。

先看操作数，再看结果变量

表达式使用什么运算，取决于操作数的类型，不取决于最终赋值变量。两个 int 相除得到 int，向零截断；先发生截断再赋值给 double，丢掉的小数不会恢复。需要小数时，应在除法之前把一个操作数变成浮点数。整数除以零会抛出 ArithmeticException；浮点除以零则可能得到 Infinity 或 NaN，因此不能把它们混为一谈。

片段：放在 main 方法体内，无额外 import。

double a = 5 / 2;         // 2.0
double b = 5 / 2.0;       // 2.5
double c = (double) 5 / 2; // 2.5
System.out.println(-5 / 2); // -2，向零截断
System.out.println(-5 % 2); // -1，余数符号跟随被除数

溢出不会自动升级为大整数

普通 int 和 long 运算溢出时会按固定位宽回绕，不会自动变成 BigInteger，也不一定抛异常。尤其要注意先算后转：long size = 100_000 * 100_000 仍然先用 int 乘法。需要检测溢出时，使用 Math.addExact、multiplyExact 等方法；需要任意精度整数时再考虑 BigInteger。

片段：放在 main 方法体内，无额外 import。

int max = Integer.MAX_VALUE;
System.out.println(max + 1); // -2147483648
long safe = 100_000L * 100_000; // 10000000000
// Math.addExact(max, 1); // 会抛 ArithmeticException
int n = 1;
int old = n++; // old 为 1，n 为 2
int now = ++n; // now 为 3，n 为 3

++ 和 -- 同时有取值与修改副作用。前置先修改，后置先取旧值。不要在一条复杂表达式里反复改变同一变量，拆成多行更容易审查。+ 同时支持加法和字符串拼接，"sum=" + 1 + 2 得到 sum=12；要先算数，应写 "sum=" + (1 + 2)。

相同对象与相同内容

基本类型的 == 比较值；引用类型的 == 比较是否指向同一对象。比较字符串内容通常使用 equals。不要因为字符串字面量驻留，或者 Integer 对象缓存，让几个 == 示例“碰巧成功”，就把它推广成内容比较。equals 的语义由类定义，数组甚至不会默认按元素比较。

片段：放在 main 方法体内；文件顶部添加 import java.util.Objects;

String a = new String("java");
String b = new String("java");
System.out.println(a == b);      // false
System.out.println(a.equals(b)); // true
String nullable = null;
System.out.println(Objects.equals(nullable, "java")); // false
boolean usable = nullable != null && !nullable.isEmpty();

条件必须是 boolean

&& 和 || 采用短路求值：左边足以决定结果时，右边不执行。因此上面的非空检查可以保护后续方法调用。& 和 | 也可用于 boolean，但会计算两侧，不应随手替代。数值类型上的 &、|、^ 和移位则是位运算。if (count) 在 Java 中不合法，应明确写 count != 0。

浮点 NaN 与自己也不相等，需要用 Double.isNaN 判断。金融或统计比较不能机械套用浮点 ==；应根据业务误差要求选择容差或精确十进制类型。

动手练习

int total = 7, count = 2; 怎样得到正确的平均值 3.5？

参考答案

片段：放在 main 方法体内，无额外 import。

int total = 7;
int count = 2;
if (count == 0) {
    throw new IllegalArgumentException("count 不能为 0");
}
double average = (double) total / count;
System.out.println(average);

05 05 · 让程序按规则执行

分支、循环与控制流

用清晰的分支表达业务规则，用合适的循环遍历数据。

if 的条件不会隐式转换

if、while 和 for 的条件必须是 boolean。Java 不会把数字和字符串转换成真假值，也没有用 a || b 直接获取默认字符串的写法。if / else if 按顺序检查条件，命中第一个后不再执行后续分支；多个独立 if 则会分别判断。即使只有一行，也建议保留花括号，避免新增语句后产生歧义。

片段：放在 main 方法体内，无额外 import。

int score = 82;
String label;
if (score >= 90) {
    label = "优秀";
} else if (score >= 60) {
    label = "通过";
} else {
    label = "继续练习";
}
System.out.println(label);

switch 可以返回一个值

传统 switch 语句使用 case 冒号时，要留意忘写 break 造成的贯穿执行。Java 21 中可以优先学习箭头形式：每个分支不会自动落入下一分支。switch 表达式整体产生结果，适合“根据一个状态映射为另一个值”的任务，必须覆盖所有可能情况；普通 int 或 String 通常需要 default。

片段：放在 main 方法体内，无额外 import。

String role = "editor";
int permission = switch (role) {
    case "admin" -> 3;
    case "editor", "author" -> {
        System.out.println("允许编辑");
        yield 2;
    }
    case "viewer" -> 1;
    default -> 0;
};
System.out.println(permission);

单表达式分支直接写结果；多语句代码块使用 yield 给出当前 switch 表达式的结果。yield 不等于 return：return 退出整个方法。上面最后的分号属于变量声明。此例没有 case null，因此 role 为 null 会抛出空指针异常；真实输入要先校验，或在 Java 21 中明确设计 null 分支。

根据任务选择循环

计数循环通常用 for；次数未知、满足条件继续的任务用 while；需要至少执行一次时使用 do / while。增强 for 适合只关心每个元素、不需要索引的遍历。数组从 0 开始，合法索引为 0 到 length - 1，循环边界通常写 i < array.length，而不是小于等于。

片段：放在 main 方法体内，无额外 import。

int[] numbers = {2, 4, 6};
int sum = 0;
for (int value : numbers) {
    sum += value;
}
for (int i = 0; i < numbers.length; i++) {
    System.out.println(i + ":" + numbers[i]);
}
int remaining = 2;
while (remaining > 0) {
    remaining--;
}
int attempts = 0;
do {
    attempts++;
} while (attempts < 1);

break、continue 与作用域

break 结束最近一层循环或相应 switch；continue 跳过本轮剩余部分，进入下一轮。它们不会默认退出整个方法。嵌套循环中要特别确认控制的是哪一层。花括号内部声明的局部变量只在对应作用域有效，不能在块外继续读取。

增强 for 中给循环变量重新赋值，不会替换数组中的元素。例如 for (int n : values) { n = 0; } 不会把数组清零；需要修改数组时使用索引赋值。

动手练习

累加 1 到 10 中的奇数，使用 continue 跳过偶数。

参考答案

片段：放在 main 方法体内，无额外 import。

int sum = 0;
for (int i = 1; i <= 10; i++) {
    if (i % 2 == 0) {
        continue;
    }
    sum += i;
}
System.out.println(sum); // 25

06 06 · 拆分可复用的行为

方法、重载与参数传递

理解签名、返回值和按值传递，避免把引用误读成指针参数。

方法不是随处声明的函数

Java 的普通方法定义在类中，不能把一个命名方法再声明在另一个方法体里。一个声明通常包括访问修饰符、可选 static、返回类型、方法名、参数列表和方法体。调用普通实例方法需要对象；static 方法属于类，适合不依赖某个对象状态的操作，但不要为了方便把所有业务状态都设成 static。

完整可运行文件：MethodDemo.java

public class MethodDemo {
    static int add(int a, int b) {
        return a + b;
    }

    static double add(double a, double b) {
        return a + b;
    }

    static int sum(int... values) {
        int result = 0;
        for (int value : values) {
            result += value;
        }
        return result;
    }

    public static void main(String[] args) {
        System.out.println(add(2, 3));     // int 版本：5
        System.out.println(add(2.0, 3.0)); // double 版本：5.0
        System.out.println(sum(1, 2, 3)); // 6
        System.out.println(sum());        // 0
    }
}

重载由参数列表区分

同名方法可以有不同数量或类型的参数，这叫重载。仅改变返回类型不能构成合法重载。编译器根据调用点的参数类型选择可匹配的方法，不是运行时看到值“像整数”就临时改变签名。自动转换、装箱和可变参数会影响候选方法，初学阶段避免设计多个非常相近的重载，否则 null 等实参可能导致调用歧义。

int... values 是可变参数，方法内部把它当作 int[] 使用。可变参数只能有一个，并且必须放在参数列表最后；调用者可以传零个或多个整数，也可以传已有 int[]。Java 没有 JavaScript 那样直接在参数声明里写默认值的常规语法，通常用重载提供默认行为。

return 终止当前方法

非 void 方法正常完成时必须返回兼容类型的值；所有正常路径都要有返回结果。void 方法可以用 return; 提前结束，但不能返回一个普通值。return 不只是“交出结果”，它也意味着该方法后面的代码不再执行，因此经常用于参数检查后的提前退出。

Java 始终按值传递

基本类型参数接收数值的副本；引用类型参数接收引用值的副本。两份引用可以指向同一个对象，所以方法能够修改对象内部状态；但是把形参重新指向另一个对象，不会改写调用方变量。这与 JavaScript 中对象参数的常见表现很相似，不应称为“对象按引用传递”。

完整可运行文件：ValueDemo.java

public class ValueDemo {
    static void change(int number, int[] items) {
        number = 99;          // 只改变形参的副本
        items[0] = 99;        // 修改双方指向的数组
        items = new int[]{7}; // 只改变形参引用
    }

    public static void main(String[] args) {
        int n = 1;
        int[] values = {1};
        change(n, values);
        System.out.println(n);         // 1
        System.out.println(values[0]); // 99
    }
}

方法参数命名应表达含义，避免大量 a、b、data。把校验、计算与输出拆开，可以让核心逻辑更容易测试。也要留意方法是否修改传入集合，避免调用方误认为它只是计算。

String 不可变，变量可以重新绑定

    builder.append(i).append(",");

int[] values = new int[3] 创建长度为 3 的数组，元素初始为 0；String[] 默认元素为 null。数组通过 length 字段获取长度，字符串用 length() 方法，集合用 size() 方法。数组索引越界会抛异常，不像 JavaScript 越界读取通常得到 undefined。

数组直接 println 往往显示类型与标识信息，不会按元素列出；用 Arrays.toString，嵌套数组可用 Arrays.deepToString。ArrayList<Integer> 的 remove(1) 删除索引 1，remove(Integer.valueOf(1)) 才是删除值 1。

类、对象与封装

从 TypeScript 的 class 出发，理解 Java 对象的创建、状态与访问边界。

类定义结构，对象保存状态

Java 的类既是类型，也是对象的构造蓝图。变量保存对象引用，而不是对象本身；把一个引用赋给另一个变量，不会复制对象。与 TypeScript 不同，Java 的字段类型在运行前受到编译器约束，且对象结构不能在运行时随手增加属性。字段有默认值：整数为 0、boolean 为 false、引用为 null；方法内的局部变量则必须先明确赋值才能读取。

构造器与类同名且没有返回类型，负责建立合法的初始状态。一旦声明任何构造器，编译器就不再提供无参构造器。this 表示当前对象，常用于区分同名参数和字段；this(...) 可以调用本类另一构造器，在 Java 21 中必须放在构造器第一条语句。

完整文件：Account.java；无须 import。

public class Account {
    private final String owner;
    private int balance;
    public Account(String owner) { this(owner, 0); }
    public Account(String owner, int balance) {
        if (owner == null || balance < 0) {
            throw new IllegalArgumentException("invalid account");
        }
        this.owner = owner;
        this.balance = balance;
    }
    public void deposit(int amount) {
        if (amount <= 0) throw new IllegalArgumentException("amount");
        balance = Math.addExact(balance, amount); // 溢出时拒绝更新
    }
    public int balance() { return balance; }
    public static void main(String[] args) {
        Account a = new Account("Lin");
        Account b = a;
        b.deposit(20);
        System.out.println(a.balance()); // 20：指向同一个对象
    }
}

让对象负责维护规则

private 字段不是“多写 getter/setter”的仪式。它允许对象统一执行校验，避免调用者直接把余额改成负数。不要机械地为每个字段生成 setter。public 是对外契约；private 只在所属顶层类及其嵌套类型范围内访问；不写修饰符表示包可见；protected 允许同包访问，并向跨包子类开放受限制的继承访问，它不等于“全项目可见”。

package 是命名空间和访问边界，不是 JavaScript 的 export。通常文件路径与包名对应；import 仅让源码能使用短名称，不会复制代码、创建对象或导入某个包下的子包。public 顶层类的文件名应与类名一致。

完整类型文件：demo/Counter.java。它没有 main，供其他类创建实例；在其上级目录执行 javac -d out demo/Counter.java 仅编译，不直接启动。

package demo;
import java.util.concurrent.atomic.AtomicInteger;

public class Counter {
    private static final AtomicInteger TOTAL = new AtomicInteger();
    public Counter() { TOTAL.incrementAndGet(); }
    public static int total() { return TOTAL.get(); }
}

static 与 final 是不同维度

实例字段属于每个对象；static 字段属于类，所有实例共享。static 方法没有 this，不能直接读取某个实例的字段。常量通常写作 public static final，并用大写下划线命名。final 字段只能初始化一次，但当它保存对象引用时，不保证对象内容不变。上例 TOTAL 不能重新指向别的对象，却可以递增内部计数。

共享 static 可变字段在后端会遇到并发访问；不要把请求用户、订单等请求级数据放进去。演示中的 AtomicInteger 只解决计数更新的原子性，不意味着任意复杂业务操作都自动线程安全。

09 组织可替换的行为

继承、接口与多态

理解 Java 的单继承、多接口、动态分派，以及何时应优先组合。

继承表达“是一种”

extends 建立子类型关系：Dog 是 Animal，因此 Animal 引用可以指向 Dog 对象。类只能直接继承一个类，但可以实现多个接口。构造器不会被继承，子类通过 super(...) 初始化父类部分；Java 21 中它必须位于构造器第一条语句。省略时编译器会尝试插入 super()，如果父类没有可访问的无参构造器就会报错。

实例方法调用根据实际对象选择实现，这叫动态分派。引用声明类型决定“编译时能调用哪些成员”，实际对象类型决定“运行时执行哪个重写方法”。@Override 让编译器检查重写关系，拼错方法名或参数时能及时报错。重写不能缩小可见性，也不能增加更宽的受检异常；返回类型可以协变。

完整文件：PolymorphismDemo.java；无须 import。

abstract class Animal {
    protected final String name;
    Animal(String name) { this.name = name; }
    abstract String sound();
}
class Dog extends Animal {
    Dog(String name) { super(name); }
    @Override String sound() { return name + ": woof"; }
}
public class PolymorphismDemo {
    public static void main(String[] args) {
        Animal animal = new Dog("Milo");
        System.out.println(animal.sound()); // Milo: woof
    }
}

抽象类共享基础，接口规定能力

abstract 类不能直接 new，可以保存实例字段、提供构造器和普通方法，也可以声明没有方法体的抽象方法。接口适合描述跨类的能力契约，接口普通抽象方法默认 public abstract，实现时必须 public。接口字段默认 public static final，不适合保存每个对象的状态。default 方法可以提供默认实现，但不是给每个实现类自动注入实例字段。

完整文件：InterfaceDemo.java；无须 import。

interface Named {
    String name();
    default String label() { return "Hello " + name(); }
}
interface Tagged {
    default String label() { return "tag"; }
}
class User implements Named, Tagged {
    @Override public String name() { return "Ada"; }
    @Override public String label() {
        return Named.super.label(); // 明确解决两个默认实现的冲突
    }
}
public class InterfaceDemo {
    public static void main(String[] args) {
        System.out.println(new User().label());
    }
}

两个互不相关的接口提供同签名 default 方法时，类必须明确消除冲突。已有父类的具体实例方法通常优先于接口默认方法。接口还可以声明 static 和 private 辅助方法；接口的 static 方法通过接口名调用，不作为实例方法继承。

不要混淆重写与重载

重载是同名但参数列表不同，编译时根据参数的声明类型选择；仅返回类型不同不构成重载。字段不参与动态分派，static 方法是隐藏而不是重写，private 方法不被子类重写，final 方法禁止重写，final 类禁止继承。尽量避免在构造器中调用可被重写的方法，因为子类字段此时可能尚未初始化。

多数业务扩展先考虑组合

组合表达“有一个”：订单服务持有一个通知器，而不是继承通知器。这样业务逻辑与发送渠道可以独立变化，也便于测试时替换为内存实现。继承并不只是复用代码的快捷键；只有调用者确实能把子类当成父类使用、契约仍然成立时，子类型关系才可靠。

enum、record 与 sealed

用有限取值、数据载体和封闭类型层级表达业务状态。

enum：用类型限制合法状态

不要让订单状态一直是自由字符串。enum 定义有限的命名实例，拼写错误会成为编译错误，switch 也能检查是否覆盖所有情况。枚举常量是对象，可以有字段和方法；构造器不能由外部直接调用。比较枚举可以使用 ==。不要把 ordinal() 当作持久化业务编号：插入或调整枚举顺序会改变它，应定义稳定的显式代码。

完整文件：StatusDemo.java；无须 import。

enum Status {
    NEW("N"), PAID("P"), CANCELLED("C");
    private final String code;
    Status(String code) { this.code = code; }
    String code() { return code; }
}
public class StatusDemo {
    public static void main(String[] args) {
        Status status = Status.PAID;
        String text = switch (status) {
            case NEW -> "待支付";
            case PAID -> "已支付";
            case CANCELLED -> "已取消";
        };
        System.out.println(text + status.code());
    }
}

record：简洁的数据载体

record 根据组件生成 private final 字段、同名访问器、构造器以及基于组件的 equals、hashCode、toString。访问器写 user.name()，不是 getName()。record 隐式 final，不能继承其他类，但可以实现接口。它适合请求参数、查询结果等数据载体，不意味着所有领域实体都应该改成 record。

紧凑构造器省略参数列表，可以检查或规范化参数；执行体结束后由编译器为组件字段赋值。record 只提供浅层不可变性：列表字段的引用不能换，但外部可能继续修改列表内容。可以复制集合隔离容器修改；集合中的元素若仍可变，就依然不是深层不可变。

完整文件：Team.java；包含所需 import。

import java.util.List;
public record Team(String name, List<String> members) {
    public Team {
        if (name == null || name.isBlank()) {
            throw new IllegalArgumentException("name");
        }
        members = List.copyOf(members); // 拷贝且不可修改，拒绝 null 元素
    }
}

sealed：封闭但不止一个实现

sealed 接口或类限制直接子类型，permits 列出许可类型。直接实现类必须是 final、sealed 或 non-sealed；record 隐式 final，恰好适合承载每种结果的数据。同一命名模块内可跨包，未命名模块中许可子类型必须在同包。它与 TypeScript 的可辨识联合类型相近，但通过真实的子类型建立变体。

完整文件：ResultDemo.java；Java 21，无须预览特性或 import。

sealed interface Result permits Success, Failure {}
record Success(String value) implements Result {}
record Failure(String message) implements Result {}
public class ResultDemo {
    static String render(Result result) {
        return switch (result) {
            case null -> "无结果";
            case Success s when s.value().isBlank() -> "空内容";
            case Success s -> s.value();
            case Failure f -> "失败：" + f.message();
        };
    }
    public static void main(String[] args) {
        Object value = new Success("ok");
        if (value instanceof Success s) {
            System.out.println(s.value());
        }
        System.out.println(render(new Failure("timeout")));
    }
}

instanceof 模式把检查和局部变量绑定合在一起，变量只在编译器能证明匹配成功的范围内可用；null instanceof Success 为 false。switch 模式按从上到下匹配，宽泛模式放在窄模式前可能导致后者不可达。when 是守卫条件，带条件的分支通常不能替代无条件分支完成穷尽性检查。

switch 表达式必须穷尽所有可能情况；Java 21 的增强 switch 语句也有穷尽要求。这里 sealed 层级已覆盖 Success 和 Failure，因此不需要 default。null 是独立问题：没有 case null 时，选择器为 null 会抛 NullPointerException，default 并不会自动接住它。

将 Pending 加入 permits 列表，并为 switch 增加 case Pending p -> "请在 " + p.retryAfterSeconds() + " 秒后重试";。遗漏分支会使这个 switch 表达式不能编译，这是封闭层级帮助定位变更影响的价值。

数据建模时可以先问三个问题：只有几个固定值且不携带各自的数据吗？使用枚举。只需要一组命名数据并希望按内容比较吗？考虑 record。不同状态携带不同字段，并希望新增状态时编译器提醒所有处理点吗？考虑 sealed 配合多个 record。不要为了展示新语法把简单的两三个字段拆成复杂层级；模型应该减少非法状态，而不是增加阅读负担。

泛型、边界与通配符

理解泛型不变性、PECS 与类型擦除，而不是背诵尖括号。

泛型把类型关系写进契约

List<String> 表示列表元素是 String，读取不再需要手动强转，错误插入会被编译器阻止。泛型参数只能使用引用类型，整数要写 Integer 而不是 int，装箱由编译器协助完成。类可以声明类型参数，方法也能声明自己的类型参数；泛型方法的 <T> 位于返回类型之前。

完整文件：Box.java；无须 import。

public class Box<T> {
    private final T value;
    public Box(T value) { this.value = value; }
    public T get() { return value; }
    public static <T> T first(T left, T right) { return left; }
    public static void main(String[] args) {
        Box<String> box = new Box<>("hello");
        String result = box.get();
        System.out.println(result);
    }
}

为什么 List<Integer> 不是 List<Number>？

Integer 是 Number 的子类型，但 List<Integer> 不是 List<Number> 的子类型，这叫不变性。如果允许赋值，就能通过 Number 列表引用插入 Double，破坏原列表“只有 Integer”的承诺。不要将它与 Java 数组的协变混淆；数组可能在运行时抛 ArrayStoreException，而泛型更早阻止这类错误。

当算法只需要数值能力，可以通过有界参数 <T extends Number> 限制 T，或使用通配符 List<? extends Number> 接受未知的 Number 子类型。这里 extends 表达上界，即使边界是接口也使用 extends。多重边界写作 <T extends Base & Comparable<T>>，若包含类，类边界必须放在最前。

完整文件：BoundsDemo.java；包含所需 import。

import java.util.List;
public class BoundsDemo {
    static <T extends Number> double twice(T value) {
        return value.doubleValue() * 2;
    }
    static double sum(List<? extends Number> values) {
        double total = 0;
        for (Number n : values) total += n.doubleValue();
        return total;
    }
    public static void main(String[] args) {
        System.out.println(sum(List.of(1, 2, 3))); // 6.0
        System.out.println(twice(2.5)); // 5.0
    }
}

PECS：生产者 extends，消费者 super

从容器读取 T，它是生产者，使用 ? extends T；向容器写入 T，它是消费者，使用 ? super T。List<? extends Number> 的实际类型可能是 List<Integer>，所以不能随便加入 Double 或 Integer，除了 null 无法安全加入具体值。它并非不可变集合：clear 等操作仍可能允许，取决于具体实现。

List<? super Integer> 的实际类型可以是 Integer、Number 或 Object 的列表，因此可以写入 Integer；但读取只能保证得到 Object。List<?> 表示未知元素类型，通常用于只需观察容器而不关心元素类型的代码。它与原始类型 List 不同：原始类型绕开泛型检查，应避免使用。

代码片段：放入任意类中；补充 import java.util.List;。

static <T> void copy(List<? extends T> source,
                     List<? super T> target) {
    for (T item : source) target.add(item);
}

类型擦除带来的边界

泛型主要由编译器检查。擦除后，未限定的类型参数通常变为 Object，有界参数变为首个边界，编译器会插入必要的转换。运行时不能直接检查 instanceof List<String>，但可以检查 instanceof List<?>。也不能直接 new T() 或 new T[10]；需要工厂、Class 对象或其他明确创建方式。泛型签名可能保留在元数据中供反射读取，因此“擦除”不等于一切类型信息都消失。

练习：为什么这两个重载不合法？

同一个类中声明 void show(List<String> x) 与 void show(List<Integer> x)。

参考答案

两个签名擦除后都是 show(List)，产生冲突。应使用不同的方法名、不同的可区分参数，或将真正通用的逻辑写为一个泛型方法；不能仅依赖泛型实参区分重载。

设计方法签名时，不必见到集合就添加通配符。如果方法既要读取又要写入同一种类型，直接 List<T> 往往更准确。如果两个参数之间有类型关系，用命名的类型参数 T 将它们连接起来；如果仅有一个未知类型且不需要关联其他参数，通配符常常更简洁。通配符不是让编译器放弃检查，恰恰是明确哪些操作安全、哪些必须禁止。遇到错误时，先判断数据流向，再决定上下界。

集合、相等性与排序

掌握 List、Set、Map 的选择、可变性边界和安全遍历。

先选语义，再选实现

List 是有顺序、允许重复、支持索引的序列，常用 ArrayList；Set 表达元素唯一，HashSet 不保证遍历顺序，LinkedHashSet 保持插入顺序；Map 保存键值映射，键唯一且不是 Collection 的子接口，HashMap 不保证迭代顺序。需要键排序时考虑 TreeMap；需要按插入顺序展示时用 LinkedHashMap。后端接口不应依赖 HashMap 当前偶然出现的顺序。

优先用接口声明变量，例如 List<String> names = new ArrayList<>()，让调用者依赖能力而不是实现。ArrayList 随机访问快，中间插入可能移动元素；不要因为 LinkedList 支持链表就认为它在业务场景一定更快。先关注语义与代码清晰度，再基于测量优化。

import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;
public class CollectionsDemo {
    public static void main(String[] args) {
        List<String> words = new ArrayList<>(List.of("java", "web", "java"));
        Map<String, Integer> counts = new HashMap<>();

相等性决定去重与查找

对象的 == 比较引用身份，equals 比较类型定义的逻辑相等。Object 默认 equals 也是身份比较，因此普通业务类若要按内容去重，需要正确重写 equals 和 hashCode；record 已生成基于组件的实现。相等对象必须拥有相同 hashCode，不相等对象可以哈希冲突。仅重写其中一个，会导致 HashSet 或 HashMap 的表现违反预期。

用作哈希键或集合元素的对象，其参与 equals/hashCode 的字段在存储期间不要改变。否则对象还在桶里，contains 或 remove 却可能找不到它。TreeSet 与 TreeMap 按比较结果是否为 0 判断重复，比较器最好与 equals 保持一致。

代码片段：放入 main 方法；补充 import java.util.HashSet; 与 import java.util.Set;。

record UserId(long value) {}
Set<UserId> ids = new HashSet<>();
ids.add(new UserId(7));
ids.add(new UserId(7));
System.out.println(ids.size()); // 1，record 按组件相等

可修改、定长、不可修改不是一回事

new ArrayList<>() 可以增加、删除和替换元素。Arrays.asList 得到与原数组关联的定长列表，能 set 但不能 add/remove。List.of、Set.of、Map.of 提供不可修改的集合，修改操作会抛 UnsupportedOperationException；它们不接受 null 元素、键或值。Set.of 拒绝重复元素，Map.of 拒绝重复键，而 List.of 允许重复。

Collections.unmodifiableList 返回只读视图：原列表变更仍可从视图看到。List.copyOf 形成不可修改的元素快照，但不深拷贝元素。HashMap 允许一个 null 键和 null 值，这与 Map.of 不同；get 返回 null 无法区分缺失键和存在但值为 null，可用 containsKey 确认。一般业务代码尽量用清晰的非 null 契约。

代码片段：放入 main 方法；补充 import java.util.ArrayList;、java.util.List;、java.util.Comparator;。

record User(String name, int age) {}
List<User> users = new ArrayList<>(List.of(
    new User("Bo", 21), new User("Ada", 21), new User("Chen", 18)));
users.sort(Comparator.comparingInt(User::age).thenComparing(User::name));
System.out.println(users); // Chen, Ada, Bo 的顺序

Comparator 描述外部排序规则，Comparable 描述类型的自然顺序。不要用 a.age() - b.age() 代替比较器，极端值可能溢出。增强 for 循环中直接调用集合 remove 通常会触发并发修改检查，即使单线程也可能发生；使用 removeIf、Iterator.remove 或新建结果集合。fail-fast 检查不是线程安全保证。

练习：删除整数 1

对于 ArrayList<Integer>，list.remove(1) 删除什么？

参考答案

它调用 remove(int index)，删除索引 1 的第二个元素。要删除值为 1 的第一个元素，使用 list.remove(Integer.valueOf(1))，让重载选择 remove(Object)。不存在时返回 false。

遍历 Map 时，如果同时需要键和值，优先使用 entrySet，避免遍历 keySet 后再逐个 get。集合的 size 是方法而非属性；数组则使用 length 字段。集合没有 JavaScript 对象那种隐式字符串键转换，整数键与字符串键是不同对象。还要注意普通集合通常不是线程安全的；把一个 ArrayList 放进多个请求共享的字段，并不会因为接口类型是 List 就获得同步保护。

异常、资源与错误边界

区分受检异常和运行时异常，让错误信息与资源管理可靠可控。

异常是控制流，不是普通返回值

throw 抛出一个异常对象并立即离开当前执行路径；throws 写在方法签名中声明可能抛出的异常类型，它本身不执行抛出操作。调用栈逐层寻找匹配的 catch，没有找到则当前线程异常终止。不要把 Java 的受检异常理解成 JavaScript Promise rejection：它是编译器对调用者施加的处理义务，与异步无关。

Throwable 下主要分为 Error 和 Exception。Error 通常表示虚拟机或环境严重问题，不应一般性捕获后假装继续成功。Exception 中除 RuntimeException 及其子类外，通常是受检异常：调用者必须 catch 或通过 throws 继续声明。运行时异常如 IllegalArgumentException、NullPointerException 不强制声明，但仍然应在合适的业务边界处理或避免。

完整文件：ReadDemo.java；包含所需 import。

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
public class ReadDemo {
    static String readConfig(Path path) throws IOException {
        return Files.readString(path);
    }
    public static void main(String[] args) {
        try {
            System.out.println(readConfig(Path.of("config.txt")));
        } catch (IOException e) {
            System.err.println("读取配置失败：" + e.getMessage());
        }
    }
}

catch 越具体越好，原因链不要丢

catch 从上到下匹配，子类异常应写在父类异常前面，否则后面的分支不可达。多个没有继承关系的异常可以用 catch (A | B e) 合并。捕获后要恢复、转换或向上抛出，不要留空 catch；仅打印日志然后返回“成功”通常会让数据状态变得难以判断。

自定义异常应表达调用者能理解的失败语义。如果要转换底层异常，构造时传入 cause，保留完整原因链。选择 checked 还是 unchecked 取决于接口契约及调用者恢复策略，而不是“所有业务异常都必须继承某一种”的机械规则。不要将数据库密码、令牌或完整内部堆栈直接返回给前端。

完整文件：ValidationDemo.java；无须 import。

class InvalidAgeException extends RuntimeException {
    InvalidAgeException(String message) { super(message); }
    InvalidAgeException(String message, Throwable cause) { super(message, cause); }
}
public class ValidationDemo {
    static int parseAge(String text) {
        final int age;
        try { age = Integer.parseInt(text); }
        catch (NumberFormatException e) {
            throw new InvalidAgeException("年龄必须为整数", e);
        }
        if (age < 0) throw new InvalidAgeException("年龄不能为负数");
        return age;
    }
}

finally 与自动资源关闭

finally 一般在 try/catch 离开前执行，包括 return 或异常退出；但进程被终止、JVM 崩溃等情况下不能保证执行。不要在 finally 中 return 或抛新的异常，它可能覆盖原本的返回值或异常，让真正故障被掩盖。释放文件、数据库连接等资源优先使用 try-with-resources，而不是手动在 finally 中逐个关闭。

完整文件：LinesDemo.java；包含所需 import。

import java.io.BufferedReader;
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
public class LinesDemo {
    static String firstLine(Path path) throws IOException {
        try (BufferedReader reader = Files.newBufferedReader(path)) {
            return reader.readLine(); // 空文件返回 null
        } // 正常返回或抛异常时都自动 close
    }
}

资源必须实现 AutoCloseable，可在括号内声明多个，关闭顺序与声明顺序相反。若 try 主体和 close 同时抛异常，主体异常是主要异常，关闭异常作为 suppressed exception 保留，可以通过 getSuppressed() 查看。不要将这种机制与 cause 原因链混为一谈。

练习：谁负责处理受检异常？

参考答案

没有声明时会编译失败。可以在 main 声明 throws IOException，把失败交给运行环境；也可以在当前层捕获并提供明确失败提示。真实服务通常在靠近请求入口的统一边界把内部异常转换为合适响应，而不是每一层都捕获、记录再原样抛出，造成重复日志。

把异常策略作为接口设计的一部分：无记录可以是正常的 Optional.empty，而输入格式错误可以抛出校验异常，基础设施不可用则是另一类失败。不要将所有不同情形都转换成 null，否则调用者无法判断是正常缺失还是系统故障。相反，也不应把每一次正常的分支选择都写成抛出并捕获异常。

Lambda、Stream 与 Optional

把前端熟悉的函数式写法迁移到 Java，同时理解类型和执行时机。

Lambda 必须有目标接口类型

Java Lambda 不是独立的任意函数对象，而是函数式接口的实现。函数式接口只有一个抽象方法，可以另有 default 或 static 方法；@FunctionalInterface 让编译器验证这一点。常见接口包括 Predicate<T> 判断条件、Function<T,R> 转换、Consumer<T> 消费和 Supplier<T> 生产值。

完整文件：LambdaDemo.java；包含所需 import。

import java.util.function.Function;
import java.util.function.Predicate;
public class LambdaDemo {
    public static void main(String[] args) {
        int minimum = 3;
        Predicate<String> longEnough = s -> s.length() >= minimum;
        Function<String, Integer> length = String::length;
        System.out.println(longEnough.test("Java")); // true
        System.out.println(length.apply("Java")); // 4
        // minimum++; // 取消注释后不再是 effectively final，捕获失败
    }
}

Lambda 捕获的局部变量必须是 final 或 effectively final，也就是赋值后没有再次改变。限制的是变量引用，不是对象内容；可以捕获一个列表后修改它，但在并发或 Stream 中这样做经常引入隐蔽副作用。Lambda 中的 this 指向外围实例，不像匿名内部类那样引入新的 this。方法引用是满足相同签名时的简写：String::length 引用实例方法，Integer::parseInt 引用静态方法，ArrayList::new 引用构造器。

Stream 是一次性、惰性的处理管道

集合保存数据，Stream 描述如何处理数据。filter、map、flatMap 等中间操作通常惰性执行，直到终端操作触发。filter 保留满足条件的元素；map 一对一转换；flatMap 将每个元素产生的流展开。流只能消费一次，终端操作后不能重复使用。它与 JavaScript Array.map 最大的直觉差别之一就是执行时机。

完整文件：StreamDemo.java；包含所需 import。

import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;
public class StreamDemo {
    public static void main(String[] args) {
        List<List<String>> groups = List.of(List.of("java", "js"), List.of("java", "sql"));
        List<String> names = groups.stream()
            .flatMap(List::stream)
            .filter(s -> s.length() > 2)
            .map(String::toUpperCase)
            .distinct()
            .toList();
        System.out.println(names); // [JAVA, SQL]
        int total = List.of(1, 2, 3).stream().reduce(0, Integer::sum);
        Map<Integer, List<String>> byLength = names.stream()
            .collect(Collectors.groupingBy(String::length));
        System.out.println(total); // 6
        System.out.println(byLength);
    }
}

终端操作与副作用边界

reduce 将元素合并为一个值，累加操作应满足结合律，初始值应是运算的单位元；求和的 0 合理，求积应使用 1。collect 适合构建可变结果容器、分组和计数。数值计算可用 mapToInt(...).sum() 避免反复装箱。Stream.toList() 返回不可修改的列表，但元素仍可能可变；Collectors.toList() 不承诺具体类型或可修改性。明确需要可变列表时使用 Collectors.toCollection(ArrayList::new)。

不要依赖 peek 或 map 中的打印、计数等副作用完成业务，因为短路操作或优化可能跳过部分遍历。anyMatch、findFirst 等可以提前结束；parallelStream 并非自动加速按钮，遇到共享可变状态、阻塞 I/O 或顺序依赖时尤其要谨慎。简单循环更清楚时，直接用循环。

Optional 表达“结果可能缺失”

Optional 适合作为可能无结果的方法返回类型，不要习惯性给每个字段和参数都包一层。of 不接受 null，ofNullable 接受，empty 表示缺失。不要无条件 get；优先 map、flatMap、orElseGet、orElseThrow。orElse 的参数会先求值，即使有结果也执行；orElseGet 的 Supplier 只在缺失时调用。

练习：只在没有名称时生成默认值

把可能为 null 或空白的输入规范化，必要时调用默认值生成函数。

参考答案

代码片段：两个方法放入任意类；补充 import java.util.Optional;。

static String defaultName() { return "Guest"; }
static String normalize(String input) {
    return Optional.ofNullable(input)
        .map(String::trim)
        .filter(s -> !s.isEmpty())
        .orElseGet(() -> defaultName());
}

map 对存在的值进行转换，filter 把不满足条件的值变成 empty。这里也可写 orElseGet(类名::defaultName)。若 map 中的方法本身返回 Optional，应考虑 flatMap，避免嵌套 Optional。

函数式接口的方法签名也决定异常边界。例如 Function.apply 没有声明 IOException，所以在 map 的 Lambda 中直接调用抛出该受检异常的方法会编译失败。可以在适当层级处理或转换异常，也可以选择显式循环以保持错误逻辑清晰。不要仅为凑成一条链就吞掉异常；可读的失败路径比语法上的简短更重要。

标准库：时间、文件与网络

掌握后端最常遇到的日期、文本文件、HTTP 与数据库接口。

1. 时间不是一个类型就够了

LocalDate 表示不含时区的日历日期，适合生日、账单日期；Instant 表示时间线上的瞬间，适合事件时间戳；ZonedDateTime 同时携带地区时区，适合展示某地时间。不要把没有时区的日期时间直接当成全球唯一时间。夏令时可能让当地某些时间不存在或出现两次。

完整示例，保存为 TimeDemo.java。执行 javac TimeDemo.java 和 java TimeDemo。

import java.time.Instant;
import java.time.LocalDate;
import java.time.ZoneId;
import java.time.ZonedDateTime;
import java.time.format.DateTimeFormatter;

public class TimeDemo {
    public static void main(String[] args) {
        LocalDate due = LocalDate.parse("2026-11-09").plusDays(7);
        Instant now = Instant.now();
        ZonedDateTime shanghai = now.atZone(ZoneId.of("Asia/Shanghai"));
        DateTimeFormatter fmt = DateTimeFormatter.ofPattern("uuuu-MM-dd HH:mm XXX");
        System.out.println(due);
        System.out.println(fmt.format(shanghai));

}

这些主要时间类型不可变，plusDays 返回新对象。DateTimeFormatter 也可安全共享。常规公历年份优先用 uuuu；不要把周基准年份 YYYY 当作普通年份。衡量代码耗时用 System.nanoTime() 的差值，而不是墙上时钟。

2. 用 Path 与 Files 操作文本

以下是方法体片段，需要导入 java.nio.file.Path、java.nio.file.Files、java.nio.charset.StandardCharsets，所在方法声明 throws java.io.IOException。Java 11 新增了这里的 writeString/readString。

Path path = Path.of("data", "notes.txt");
Files.createDirectories(path.getParent());
Files.writeString(path, "学习 Java\n", StandardCharsets.UTF_8);
String content = Files.readString(path, StandardCharsets.UTF_8);
System.out.println(content);

writeString 默认会覆盖原文件。大文件不要一次全部读入内存，可用 Files.lines 并通过 try-with-resources 关闭流。相对路径以进程工作目录为准，不一定是源码目录；处理用户提供的路径时还要校验允许访问的目录。

3. HTTP 不是 fetch 的逐字翻译

完整 Java 21 示例，保存为 HttpDemo.java。标准 HttpClient 自 Java 11 提供；连接超时与请求超时分别约束不同阶段。真实服务通常复用客户端。

import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.time.Duration;
import java.io.IOException;

public class HttpDemo {
    public static void main(String[] args) {
        try (HttpClient client = HttpClient.newBuilder()
                .connectTimeout(Duration.ofSeconds(5)).build()) {
            HttpRequest request = HttpRequest.newBuilder()
                .uri(URI.create("https://dev.java/"))
                .timeout(Duration.ofSeconds(10)).GET().build();
            HttpResponse<String> response = client.send(
                request, HttpResponse.BodyHandlers.ofString());
            if (response.statusCode() / 100 != 2) {
                throw new IOException("HTTP 状态 " + response.statusCode());
            }
            System.out.println(response.body().length());
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            System.err.println("请求已中断");
        } catch (IOException e) {
            System.err.println("请求失败：" + e.getMessage());
        }
    }
}

HTTP 404/500 不会自动变成 Java 异常，必须检查状态码。示例只打印长度，避免把响应里的私人数据直接记入日志。

4. JDBC：参数绑定而不是字符串拼接

JDBC 是数据库访问标准接口，还需要数据库驱动和连接配置。以下为方法体片段，假设已有 java.sql.Connection connection 与 long id，方法处理或声明 SQLException。

try (var stmt = connection.prepareStatement(
        "SELECT name FROM users WHERE id = ?")) {
    stmt.setLong(1, id);
    try (var result = stmt.executeQuery()) {
        while (result.next()) System.out.println(result.getString("name"));
    }
}

? 绑定值，不能绑定表名；动态表名必须由允许列表决定。连接通常来自连接池，真实业务还要学习事务、回滚和资源归还。

并发：线程、任务与共享状态

先学任务生命周期，再学如何避免竞争条件。

1. 线程与异步不是同一回事

浏览器里的 JavaScript 常以事件循环组织工作；Java 后端通常会同时运行多个线程。并发表示多个任务交错推进，并行表示它们在同一时刻执行。创建一个线程并不保证加速，线程调度、等待、同步都会有成本。

方法体片段，无需导入。start() 启动新线程；直接调用 run() 只是当前线程上的普通方法调用。join() 等待结束，所在方法需处理或声明 InterruptedException。

Thread thread = new Thread(() -> System.out.println("后台任务"));
thread.start();
thread.join();

2. 把任务交给 ExecutorService

完整示例，保存为 TaskDemo.java。使用 Java 21 的 ExecutorService 自动关闭支持，退出 try 时会等待任务完成，不能把它当成“立即停止所有任务”。

import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;
import java.util.concurrent.ExecutionException;
import java.util.concurrent.TimeUnit;
import java.util.concurrent.TimeoutException;

public class TaskDemo {
    public static void main(String[] args) {
        try (ExecutorService pool = Executors.newFixedThreadPool(2)) {
            Future<Integer> result = pool.submit(() -> 21 * 2);
            try {
                System.out.println(result.get(2, TimeUnit.SECONDS));
            } catch (TimeoutException e) {
                result.cancel(true);
                System.err.println("等待超时");
            } catch (InterruptedException e) {
                result.cancel(true);
                Thread.currentThread().interrupt();
            } catch (ExecutionException e) {
                System.err.println("任务失败：" + e.getCause());
            }
        }
    }
}

Future.get() 会阻塞调用线程，异常包装在 ExecutionException 里。超时只限制等待，不会自动终止任务；cancel(true) 请求中断，也不能强杀不响应中断的代码。示例任务立即完成，因此只是展示超时处理结构。

3. Java 21 的正式特性：虚拟线程

将示例中的执行器改为 Executors.newVirtualThreadPerTaskExecutor()，便会为每个任务创建虚拟线程。它们适合大量等待网络或数据库的阻塞式任务，并不会让 CPU 密集计算凭空变快。不要为复用虚拟线程而建立传统线程池；要用连接池、信号量等限制真正稀缺的资源。

Java 21 中，虚拟线程在某些 synchronized 区域或本地调用中阻塞可能固定住承载线程。先测量再优化，不要把其他 JDK 版本的改进默认套用到 Java 21。结构化并发在 Java 21 不是正式特性，本指南不依赖它。

4. volatile 不会让 count++ 变安全

count++ 是读取、计算、写回三个动作，两个线程可能覆盖彼此结果。volatile 提供可见性与相关排序保证，但不把复合操作变成原子操作。synchronized 通过同一把锁提供互斥及可见性，AtomicInteger 则提供适合单个计数值的原子操作。

类成员片段，需要导入 java.util.concurrent.atomic.AtomicInteger，放入自己的类中。

private final AtomicInteger count = new AtomicInteger();
void recordVisit() { count.incrementAndGet(); }
int visits() { return count.get(); }

private int balance;
synchronized void deposit(int amount) { balance = Math.addExact(balance, amount); // 溢出时拒绝更新 }
synchronized int balance() { return balance; }

对余额示例，读写必须都遵守同一锁。两个独立原子变量并不能自动保证“库存扣减且订单创建”的跨变量业务规则。优先使用不可变数据、线程隔离和并发集合，减少共享可变状态；普通 ArrayList、HashMap 不适合无保护的并发修改。

5. 停止也是设计的一部分

shutdown() 不再接收新任务，但允许已提交任务继续执行；shutdownNow() 尝试中断正在执行的任务。任务应在适当位置检查中断；捕获 InterruptedException 后可向上抛出，或恢复中断标记并结束当前工作。不要捕获后无条件继续循环。

练习：修复计数器

十个线程各执行一千次 volatile int count 的自增，为什么最终可能少于一万？如何验证修复？

参考答案

volatile 不保证自增原子性，更新可能丢失。改用 AtomicInteger.incrementAndGet，等待所有 Future 完成后断言结果为一万。一次测试通过不证明原代码安全，应从并发语义判断。

注解、反射与 JVM 心智模型

理解元数据、运行时类型与 Java 程序真正运行的位置。

1. 注解是元数据，不是魔法

@Override 帮编译器检查方法覆盖；它不会在运行时自动调用方法。框架里的注解之所以有效，是因为编译器、注解处理器或运行时框架读取了它们并执行约定逻辑。看到注解时，问“谁在什么时候读取它？”比死记名称更重要。

保留策略有三种：SOURCE 只在源码阶段存在；CLASS 写入 class 文件但通常不能通过运行时反射读取，也是默认策略；RUNTIME 可以在运行时读取。@Target 限定注解放在类型、方法、字段等什么位置。

完整示例，保存为 ReflectionDemo.java。一个文件可包含多个顶层类型，但这里只有文件同名的类是 public。

import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;
import java.lang.annotation.ElementType;
import java.lang.reflect.Method;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@interface Label {
    String value();
}

public class ReflectionDemo {
    @Label("问候方法")
    public String greet(String name) {
        return "你好，" + name;
    }

    public static void main(String[] args) throws ReflectiveOperationException {
        Method method = ReflectionDemo.class.getMethod("greet", String.class);
        Label label = method.getAnnotation(Label.class);
        System.out.println(label.value());
        Object value = method.invoke(new ReflectionDemo(), "Java");
        System.out.println(value);
    }
}

这个异常声明适合教学入口，不代表真实服务应把所有反射错误直接抛到用户界面。方法名或参数写错会在运行时失败，失去普通方法调用的一部分编译期保障；目标方法抛出的异常会被包装为 InvocationTargetException。

2. 反射能看到什么，不能推断什么

Class<?> 描述运行时类；Field、Method、Constructor 分别描述字段、方法和构造器。反射适用于框架、序列化工具等基础设施，普通业务代码优先使用接口与直接调用，不要为“灵活”到处写字符串方法名。

Java 泛型主要通过类型擦除实现：运行时的 ArrayList<String> 与 ArrayList<Integer> 通常具有相同的 Class。声明在字段或方法上的部分泛型签名元数据可以通过反射读取，但这不等于每个集合实例都携带可恢复的元素类型，也不能用 instanceof List<String> 检查集合元素。

反射不应被视为绕过访问控制的工具。模块的导出和开放边界会限制访问；遇到不可访问错误，应使用公开 API 或审查合法模块配置，不要默认添加广泛的开放参数来掩盖问题。

3. 从源码到运行中的进程

javac 将 .java 编译为 .class 字节码，java 启动 JVM 加载类并执行入口。JVM 可解释执行并对热点代码即时编译；因此一次很短的计时常受预热等因素影响，不能轻率宣布某种写法更快。

  • classpath：寻找传统类和 JAR 的路径，常见于初学者 Maven 应用。
  • module-path：寻找 Java 9 引入的命名模块；module-info.java 声明依赖与导出等边界，不等同于包名。
  • 栈：每个线程的方法调用帧，包含局部变量和执行状态等；过深递归可能触发 StackOverflowError。
  • 堆：对象实例主要存储的共享区域。局部引用与它指向的对象不是同一个东西，不要把“变量在栈里”理解成对象必然也在那里。

4. GC 不等于资源管理

垃圾收集器回收不再可达对象占用的内存，但回收时机不是业务逻辑能依赖的承诺。可达的无用对象仍会占用内存，例如不断增长的静态缓存。文件、数据库连接和锁需要明确释放，不能等 GC 替你关闭。先定位泄漏来源，再讨论堆大小和收集器参数。

练习：为什么取不到注解？

删除上例的 @Retention 后，getAnnotation 返回什么？能否靠强制 GC 确保文件立刻关闭？

参考答案

默认 CLASS 保留策略不提供运行时注解访问，因此返回 null，继续调用 value 会空指针。不能依赖 GC 关闭文件；应使用 try-with-resources 管理 AutoCloseable 资源。

19 质量来自可检查的习惯

写出可维护的 Java

命名、错误处理、日志、配置和调试，比背 API 更能帮助你进入团队。

1. 命名让意图可读

包名一般小写，例如 com.example.notes；类和接口用 UpperCamelCase，如 NoteRepository；方法与变量用 lowerCamelCase，如 findById；常量用 UPPER_SNAKE_CASE，如 MAX_NOTE_LENGTH。布尔方法常用 is、has、can 开头。一个方法尽量表达一个清楚的操作，不要把参数校验、数据库查询、格式化与网络发送全塞进 main。

比起 process(data, true)，清楚的方法名或枚举参数更容易审查。避免为了套用设计模式而过度拆分；先做到依赖方向清楚、核心逻辑可测试，再根据真实变化提取抽象。

2. 错误不是返回任意默认值

输入不合法可抛 IllegalArgumentException；找不到可选结果可用 Optional；磁盘、网络和数据库故障必须明确处理或传播。把所有异常捕获后返回 null，通常会让真正原因变成后面的 NullPointerException。捕获异常时应能说明自己采取了恢复、转换、重试或退出中的哪一种策略。

完整示例，保存为 ConfigDemo.java，演示无需额外依赖的 System.Logger（Java 9 起提供）。日志 API 的具体输出由运行环境决定。

public class ConfigDemo {
    private static final System.Logger LOG =
            System.getLogger(ConfigDemo.class.getName());

    static int readPort(String value) {
        int port = value == null ? 8080 : Integer.parseInt(value);
        if (port < 1 || port > 65535) {
            throw new IllegalArgumentException("端口超出范围");
        }
        return port;
    }

    public static void main(String[] args) {
        try {
            int port = readPort(System.getenv("APP_PORT"));
            LOG.log(System.Logger.Level.INFO, "配置端口：{0}", port);
        } catch (IllegalArgumentException e) {
            LOG.log(System.Logger.Level.ERROR,
                    "APP_PORT 配置无效，请使用 1 至 65535 的整数");
            System.exit(1);
        }
    }
}

NumberFormatException 是 IllegalArgumentException 的子类，因此这一 catch 也覆盖格式错误。示例只在 CLI 入口退出；可复用的业务方法不应突然 System.exit。服务中的错误应转换成合适的响应，并保留内部诊断信息。

3. 日志与秘密要分开

日志记录“发生了什么”和定位线索，如操作名、错误类别、请求关联 ID；不要记录密码、令牌、完整个人资料、认证请求头或数据库连接秘密。异常消息和堆栈也可能包含敏感值，打印前要考虑来源。不要在每一层重复记录同一个异常，导致一次失败产生多条几乎相同的告警。

配置与源码分离。普通环境差异可通过环境变量或外置配置提供；秘密应通过合适的秘密管理方案注入，环境变量也不天然安全。不要把真实密钥写进示例、仓库、截图或 shell 历史。提交示例配置时只放说明和占位值。

4. 看懂堆栈，而不是只看最后一行

先阅读异常类型与消息，找到最接近问题的业务代码帧，再沿 Caused by 检查根因。行号必须对应实际运行的构建版本。NoSuchMethodError 可能是依赖版本不匹配，不一定是源码真的少写了方法。

5. 每次修改都能验证

  • 为正常输入、边界值、非法输入分别写测试。测试名描述行为，避免只叫 test1。
  • 把时钟、随机数、网络等不稳定因素隔离，必要时注入 Clock 或小接口。
  • 固定重要依赖与构建插件版本，定期检查安全更新；不要随意复制不明来源的依赖坐标。
  • 格式化、静态检查和代码审查是辅助工具，不替代行为测试。不要为消除警告而盲目压制所有警告。

做一个真正能重复运行的小应用

学习任务 CLI 支持添加任务、查看列表、标记完成，并把数据保存为 UTF-8 文件。它没有框架和第三方依赖，刻意让类、record、枚举、集合、Stream、异常、文件操作各司其职。不是把二十个知识点堆进一个“Hello World”，而是观察它们怎样解决同一件事。

第二步：按职责阅读代码

  1. Task record 表达一条任务，构造时校验不变量。完成任务通过创建新值实现，避免修改 record 字段。
  2. run 是应用入口逻辑，先校验命令与参数数量，再加载数据。返回 0 表示成功，1 表示文件错误，2 表示输入错误。
  3. load 把三列文本解析成类型明确的对象。遇到坏行或重复 ID 会报告行号，不静默丢弃用户数据。
  4. save 先写同目录临时文件，再替换目标文件。若文件系统不支持原子移动，会回退普通替换。这降低写入中断风险，但不是数据库事务或断电持久性保证。
  5. main 只把参数与输出交给 run，然后设置退出码。测试可以直接调用 run，不必启动新 JVM，也不会被 System.exit 中断。

完整应用：StudyTasks.java

下面是可直接保存、编译的完整文件，不需要补充导入。建议先从 main、run 的 switch 分支读起，再看文件处理。

import java.io.IOException;
import java.io.PrintStream;
import java.nio.charset.StandardCharsets;
import java.nio.file.AtomicMoveNotSupportedException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.StandardCopyOption;
import java.util.ArrayList;
import java.util.HashSet;
import java.util.List;
import java.util.Objects;

/** Java 21, standard library only. A single-user learning task CLI. */
public final class StudyTasks {
    enum Status { TODO, DONE }

    record Task(int id, String title, Status status) {
        Task {
            if (id <= 0) throw new IllegalArgumentException("ID 必须为正整数");
            title = normalizeTitle(title);
            Objects.requireNonNull(status, "status");
        }
        Task complete() { return new Task(id, title, Status.DONE); }
    }

    public static void main(String[] args) {
        System.exit(run(args, System.out));
    }

    static int run(String[] args, PrintStream output) {
        if (args.length < 2) {
            usage(output);
            return 2;
        }
        try {
            Path file = Path.of(args[0]);
            String command = args[1];
            if (!(command.equals("list") && args.length == 2)
                    && !((command.equals("add") || command.equals("done")) && args.length == 3)) {
                usage(output);
                return 2;
            }
            List<Task> tasks = load(file);
            switch (command) {
                case "list" -> {
                    if (tasks.isEmpty()) output.println("暂无任务，先用 add 添加一项。");
                    tasks.forEach(task -> output.printf("#%d [%s] %s%n", task.id(), task.status(), task.title()));
                }
                case "add" -> {
                    int maxId = tasks.stream().mapToInt(Task::id).max().orElse(0);
                    int nextId = Math.addExact(maxId, 1);
                    Task task = new Task(nextId, args[2], Status.TODO);
                    tasks.add(task);
                    save(file, tasks);
                    output.printf("已添加 #%d：%s%n", task.id(), task.title());
                }
                case "done" -> {
                    int id = Integer.parseInt(args[2]);
                    int index = -1;
                    for (int i = 0; i < tasks.size(); i++) {
                        if (tasks.get(i).id() == id) { index = i; break; }
                    }
                    if (index < 0) throw new IllegalArgumentException("找不到任务 #" + id);
                    tasks.set(index, tasks.get(index).complete());
                    save(file, tasks);
                    output.println("已完成 #" + id);
                }
                default -> throw new IllegalStateException("已校验的命令不应到达此处");
            }
            return 0;
        } catch (IllegalArgumentException | ArithmeticException e) {
            output.println("错误：" + e.getMessage());
            return 2;
        } catch (IOException e) {
            output.println("错误：无法读写任务文件。" + e.getMessage());
            return 1;
        }
    }

    private static String normalizeTitle(String title) {
        if (title == null || title.isBlank()) throw new IllegalArgumentException("标题不能为空");
        if (title.indexOf('\t') >= 0 || title.indexOf('\n') >= 0 || title.indexOf('\r') >= 0) {
            throw new IllegalArgumentException("标题不能包含制表符或换行");
        }
        return title.strip();
    }

    private static List<Task> load(Path file) throws IOException {
        List<Task> tasks = new ArrayList<>();
        if (!Files.exists(file)) return tasks;
        List<String> lines = Files.readAllLines(file, StandardCharsets.UTF_8);
        var ids = new HashSet<Integer>();
        for (int i = 0; i < lines.size(); i++) {
            String[] parts = lines.get(i).split("\t", -1);
            try {
                if (parts.length != 3) throw new IllegalArgumentException("需要 ID、状态、标题三列");
                Task task = new Task(Integer.parseInt(parts[0]), parts[2], Status.valueOf(parts[1]));
                if (!ids.add(task.id())) throw new IllegalArgumentException("ID 重复");
                tasks.add(task);
            } catch (IllegalArgumentException e) {
                throw new IOException("文件第 " + (i + 1) + " 行格式错误：" + e.getMessage(), e);
            }
        }
        return tasks;
    }

    private static void save(Path file, List<Task> tasks) throws IOException {
        Path destination = file.toAbsolutePath();
        Files.createDirectories(destination.getParent());
        Path temp = Files.createTempFile(destination.getParent(), ".study-tasks-", ".tmp");
        try {
            List<String> lines = tasks.stream()
                    .map(task -> task.id() + "\t" + task.status() + "\t" + task.title())
                    .toList();
            Files.write(temp, lines, StandardCharsets.UTF_8);
            try {
                Files.move(temp, destination, StandardCopyOption.REPLACE_EXISTING, StandardCopyOption.ATOMIC_MOVE);
            } catch (AtomicMoveNotSupportedException e) {
                Files.move(temp, destination, StandardCopyOption.REPLACE_EXISTING);
            }
        } finally {
            Files.deleteIfExists(temp);
        }
    }

    private static void usage(PrintStream output) {
        output.println("用法：java StudyTasks <数据文件> list|add <标题>|done <ID>");
        output.println("示例：java StudyTasks tasks.tsv add \"学习泛型\"");
    }
}

第三步：读懂测试，不依赖碰运气

测试文件通过 Files.createTempDirectory 隔离真实数据，用 ByteArrayOutputStream 捕获输出，检查退出码和用户可见结果。每个断言失败会主动抛出 AssertionError，因此不依赖默认关闭的 Java assert 开关。生产应用可以把这些检查迁移到 JUnit 5。

逐步试错：把 add 的标题改为空白，把 done 的 ID 改成不存在的数字，把文件手工改成错误格式，然后看程序如何拒绝输入。检查错误后再次运行 list，确认正确的数据没有因为输入错误被覆盖。
